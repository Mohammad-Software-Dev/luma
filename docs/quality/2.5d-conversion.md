# 2.5D conversion and licensed asset pass

Verified locally on 11 October 2026. Work continues on `main`.

## What changed

Three.js renders the solid world, lighting, shadows, scenery and characters behind the existing transparent gameplay-effects canvas. The perspective projection matches gameplay pixels exactly at z=0; physics, saves, input, campaign gates and all 24 room layouts retain their existing behavior. Moving platforms update from the same collision coordinates. Behind that plane, modeled trees, rocks and distant paintings occupy separate depths, producing perspective parallax as the camera travels.

The environment uses locally bundled CC0 scanned rocks, pine, ferns, a stump and seamless ground/cliff materials. Luma and Briarhorn use CC0 textured skeletal models, adapted with animation transitions and combat poses. Licensed asset sources, modifications and remaining art limitations are documented in [3D assets](../art/3d-assets.md) and [credits](../../public/art/CREDITS.md). Other guardians and regular creatures remain procedural rigs; this release does not claim a finished AAA art set.

## Performance work

An initial high-detail forest sample ran at a 32.3 ms median. The cause was unnecessary distant-tree geometry and shadows: the room-wide mesh prevented off-screen trees from being culled. Trees now retain individual visibility bounds, use an 11,920-triangle mesh in distant layers and a 65,582-triangle mesh nearby, and do not participate in the foreground shadow pass. Static terrain/decorations are batched by material. The full 1920×1080 rendering budget is retained.

Warm local browser samples, using the development review harness and a 1920×1080 backing canvas:

| Scenario | Frames | Frame median / p95 | CPU render median / p95 | Frames >25 ms |
| --- | ---: | --- | --- | ---: |
| Glade camera sweep | 179 | 16.7 / 17.7 ms | 3.6 / 5.8 ms | 4 |
| Briarhorn combat | 479 | 16.7 / 17.7 ms | 2.8 / 3.6 ms | 0 |

These are local measurements, not a guarantee for every GPU. The four longer forest frames remain visible in the result rather than being excluded. Startup decoding, shader compilation, room transitions and real mobile hardware need further profiling. The new asset package is approximately 15.1 MiB before HTTP compression; no vendor downloads happen at runtime.

## Verification

- 122 gameplay checks preserve campaign gating, traversal, boss counterplay, persistence, input and combat behavior.
- 12 renderer checks cover exact projection at several aspect ratios, six-biome geometry, moving platforms, resource ownership/disposal, crystal state, real imported skeletal animation, licensed scan loading, missing-model fallbacks and WebGL context lifecycle. GPU submission is mocked in these Node tests.
- Asset-package verification checks file hashes, license/source inventory, local resource dependencies, buffer bounds and the 16 MiB download budget.
- A real browser audit visited all 24 rooms in one renderer: every room used WebGL, no asset failures, at most 65 GPU geometries and 217 draw calls. Textures stabilized at 46 after all biomes and the stag were visited.
- Browser visual review covered the forest, scanned ledges, rabbit/stag scale and guardian warnings. Context-loss controls check the previous Canvas renderer and restoration without resetting progress.

Use `/benchmarks/render` on the development server for stage/boss previews, frozen hero poses, frame-time samples, the room audit and context-loss controls. This harness is development-only and disables save writes. A full campaign playthrough and physical controller/touch/audio checks remain separate release work.
